# 입력 모드 고도화 계획 — 표준 입력 ↔ 전화통화 모드

## 1. 목표

메인 보이스 채팅에 두 가지 입력 모드를 둔다.

- **표준 모드(STANDARD)** — 현재 UI. 텍스트 입력 + 1회용 마이크(누를 때마다 한 번 듣기).
- **전화통화 모드(CALL)** — 마이크를 매번 누르지 않아도, **마이크가 계속 열린 상태**로 자연스럽게
  말하고 듣는다. 핵심 제약: **어시스턴트의 TTS 소리가 에코로 다시 인식되지 않아야 한다.**

전환:
- 표준 모드의 **마이크-오브를 길게 누르면** 전화통화 모드로 전환. 통화 모드에서 **다시 길게 누르면**(또는
  통화 종료 버튼) 표준 모드로 복귀.
- (확장) 대화 진입 시 파라미터로 초기 모드를 지정할 수 있는 구조를 남긴다.

## 2. 에코 문제 해결 전략 — 반이중(Half-duplex) 턴테이킹

온디바이스 AEC(음향 에코 제거)는 기기/엔진별 신뢰도가 낮다. 가장 견고한 방법은 **말하는 동안 듣지 않는
것**이다.

```
[듣기] --(사용자 발화 종료/엔드포인팅)--> [생각(LLM)] --> [말하기(TTS)] --(발화 종료)--> [듣기] ...
                                   ▲                                         │
                                   └──── 말하는 중에는 마이크 닫힘 ────────────┘  ← 에코 원천 차단
```

- **말하기/생각 중에는 인식기를 시작하지 않는다.** → 어시스턴트 음성이 마이크로 들어가지 않음.
- 발화가 끝나면(또는 사용자 입력이 없으면) 짧은 디바운스 후 **자동으로 다시 듣기**를 시작한다.
- 턴 종료 감지: **시스템 `SpeechRecognizer`의 엔드포인팅**(무음 시 `onResults`/`onError` 반환)을 사용.
  (신경망 STT의 연속 모드는 VAD 필요 → 후속 단계. 통화 모드 1차는 시스템 인식기를 사용한다.)
- 보조: 신경망 녹음기는 `AudioSource.VOICE_COMMUNICATION`(AEC/NS 포함)으로 캡처(추후 신경망 연속화 대비).
- **수동 바지인(barge-in)**: 통화 모드에서 큰 오브를 탭하면 말하기를 중단하고 즉시 듣기로 전환.

## 3. 상태 머신 (단일 관찰자 패턴)

산재된 콜백마다 "다시 듣기"를 호출하면 유지보수가 어렵다. 대신 **ViewModel이 자신의 `uiState`를 collect
하는 단일 코루틴(call loop)** 으로 일원화한다.

```
재청취 조건 = inputMode==CALL && model 준비 && !isListening && !isThinking && !isSpeaking
조건이 디바운스(≈400ms) 동안 안정적으로 유지되면 → startListening()
조건이 깨지면(말하기/생각 시작) → 예약된 재청취 취소
```

- 생각→말하기 사이의 짧은 공백은 디바운스가 흡수(곧 `isSpeaking=true`로 취소됨).
- 무응답/무음 턴도 동일 경로로 자연히 재청취 → 대화가 끊기지 않음.
- 모드 종료 시 loop 취소 + `stopListening()/stopSpeaking()`.

## 4. UI 설계

### 4.1 표준 모드 (현행 유지 + 진입점)
- 하단: `[텍스트 입력 pill | 작은 마이크-오브]`.
- 작은 마이크-오브 **길게 누르기 → 통화 모드 진입**.

### 4.2 전화통화 모드 (다이얼러 통화 화면 느낌)
- 텍스트 입력 숨김. **큰 마이크-오브를 하단 중앙에 단독 배치**(상태별 색/펄스/회전).
- 상단/오브 위: 통화 상태 라벨("듣고 있어요…/생각 중…/말하는 중…")과 캐릭터 이름(배경은 캐릭터 얼굴).
- 오브 아래: **빨간 통화 종료(hangup) 버튼** → 표준 모드 복귀. 오브 **길게 누르기**로도 복귀.
- 오브 **탭** = 말하는 중이면 즉시 중단(바지인), 듣는 중이면 무동작.
- 고급스러운 미니멀: 프로스티드/글로우, 부드러운 전환 애니메이션.

### 4.3 메시지 버블 영역 (얼굴 가림 해소 + 위로 사라지는 연출)
- 버블 영역을 **화면 하단부로 내려** 캐릭터 얼굴을 가리지 않게 한다(상단에 가중치 spacer).
- `verticalArrangement = Arrangement.Bottom`으로 메시지가 적을 땐 하단에 모이게.
- **상단 페이드(top fade)**: 위로 올라갈수록 점점 투명 → "위로 사라지는" 느낌(`drawWithContent` + `DstIn`
  세로 그라데이션 마스크).
- 자동 스크롤로 최신 메시지는 항상 하단에 보임.

## 5. 모듈 구조 (가독성/추상화/재사용)

| 구성요소 | 위치 | 책임 |
| --- | --- | --- |
| `ChatInputMode`(enum STANDARD/CALL) | `customtasks/voiceassistant` | 모드 타입 |
| `inputMode` 상태 + `setInputMode`/`toggleInputMode` + call loop | `VoiceAssistantViewModel` | 모드/반이중 루프 |
| `Modifier.topFade()` | `ui/mainpage` (UI util) | 상단 페이드 마스크 |
| `MicOrb`(크기 파라미터 + 탭/롱프레스) | `ui/mainpage/MainPage.kt` | 공용 마이크 오브 |
| `StandardInputBar`(기존 InputBar) | `ui/mainpage/MainPage.kt` | 텍스트+작은 오브, 롱프레스로 통화 진입 |
| `CallControls`(신규) | `ui/mainpage/MainPage.kt` | 큰 오브 + 상태 + hangup |
| `Transcript`(하단 정렬 + topFade) | `ui/mainpage/MainPage.kt` | 버블 리스트 |

하단 영역은 `when (inputMode) { STANDARD -> StandardInputBar; CALL -> CallControls }`로 분기한다.

## 6. 구현 단계

1. **(이번 구현)**
   - `ChatInputMode` + VM `inputMode`/`setInputMode`/`toggleInputMode` + 반이중 call loop.
   - `MicOrb`에 롱프레스/크기 파라미터, 표준/통화 하단 UI 분기, `CallControls`.
   - 버블 영역 하단 이동 + `topFade`.
   - 통화 모드는 시스템 `SpeechRecognizer` 기반 연속 루프.
2. **(후속)**
   - 신경망 STT 연속화(VAD), `VOICE_COMMUNICATION` 캡처로 AEC 강화.
   - 대화 진입 파라미터로 초기 모드 지정(딥링크/캐릭터 설정).
   - 통화 모드 음소거/스피커 토글 등 다이얼러 부가 컨트롤.

## 7. 위험/한계
- 시스템 인식기는 무음 시 재시작을 반복(기기에 따라 짧은 알림음 가능).
- 진정한 동시 바지인(말하면서 끼어들기)은 AEC 없이는 불가 → 수동 탭 바지인으로 대체.
- 소형 LLM 응답 지연 동안 통화 공백이 생길 수 있음(상태 애니메이션으로 보완).
